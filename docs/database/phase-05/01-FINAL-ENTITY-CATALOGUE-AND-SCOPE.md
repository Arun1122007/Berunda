# Final Entity Catalogue and Scope

> **Document ID:** BERUNDA-PH5-ENTITY-CAT-001 | **Version:** 1.0
> **Phase:** 5 (Design and Create the Database)

## 1. P0 Required Entities

These are essential for the functioning of the core Hack2Skill challenge workflows (FIR management, Officer assignment, Station isolation).

| Logical Entity | Description |
|----------------|-------------|
| **User/Profile** | Handled by Catalyst Auth primarily, augmented via `Employee` or `UserProfile` in Data Store for auditing and roles. |
| **Role** | Role mappings (e.g., IO, Supervisor, System) via Catalyst user groups. |
| **Police Station (Unit)** | Jurisdictional boundaries for data isolation. |
| **Officer (Employee)** | The investigating officers assigning and handling FIRs. |
| **FIR (CaseMaster)** | The core record of the incident. |
| **FIR Original Source** | The un-altered text/document of the initial complaint. Must remain completely isolated from AI derivations. |
| **Persons (Accused, Victim, Complainant)** | Distinct roles involved in a FIR. |
| **Locations/Occurrence (Inv_OccurrenceTime)**| Geospatial and temporal location data. |
| **Investigation Notes** | Officer notes attached to a case. |
| **Audit Events** | Immutable logs of access, AI execution, and PII interactions. |

## 2. P1 Approved Entities

These are required for the AI and Analytics prototype functionalities, but don't strictly block base CRUD.

| Logical Entity | Description |
|----------------|-------------|
| **AI Processing Runs** | Records of when an AI model was invoked, the template used, and provider. |
| **AI Suggestions** | The raw outputs generated by the AI (must not overwrite official fields). |
| **AI Review Decisions** | The human-in-the-loop (HITL) approval, rejection, or edit of an AI suggestion. |
| **Evidence Metadata** | Links and checksums for related multimedia evidence stored in Stratus. |
| **Vehicles (VehicleLink)** | Extracted vehicle data from FIRs. |
| **FIR Status History** | State-machine log of FIR progression (e.g. Registered -> Under Investigation -> Closed). |
| **Related Case Suggestions** | AI-generated links to potentially connected FIRs based on MO or entity resolution. |

## 3. P2 / Deferred / Rejected Entities

| Logical Entity | Status | Reason |
|----------------|--------|--------|
| **CCTNS Real Time Feed** | Deferred | Future scope, requires MoU. |
| **Biometric/Aadhaar Auth** | Rejected | Strictly forbidden by Phase 1 safety rules (no real PII or Aadhaar data). |
| **Full Telecom CDRs** | Rejected | Legal scope issue for Datathon. |
| **Financial UPI Tracking** | Deferred | Out of immediate MVP scope without partner banking APIs. |
| **Property Items** | P2 / Optional| Secondary to core persons/vehicles tracking in MVP. |

## 4. Design Rule Commitments
- **No free-text lifecycle states:** All states (FIR status, Audit status, AI status) use strict approved enumerations.
- **Original Source separation:** `FIR Original Source` will **never** be updated by an AI suggestion. AI outputs belong exclusively to `AI Suggestions`.
