## 1. API Standards

### 1.1 Base Path and Versioning

```
Base:    /api/v1
Version: v1 (embedded in path; header-based versioning deferred to Phase 3+)
Protocol: HTTPS (Catalyst AppSail enforces TLS in production; HTTP accepted in local dev)
```

### 1.2 Authentication

Every endpoint except `/health`, `/ready`, `/api/v1/status`, and `POST /api/v1/auth/login` requires:

```
Authorization: Bearer <JWT_ACCESS_TOKEN>
```

JWT format: HS256, payload `{ user_id, role, district_id, assigned_stations, exp, iat, jti }`.

Access token lifetime: 15 minutes. Refresh token lifetime: 7 days (httpOnly cookie).

### 1.3 Content Types

```
Request:  application/json (default)
          multipart/form-data (file upload endpoints only)
Response: application/json
Error:    application/json
```

### 1.4 Resource Naming

- Plural nouns for collections: `/firs`, `/entities`, `/audit-logs`
- Kebab-case path segments: `/merge-queue`, `/shortest-path`, `/ai-analysis`
- Nested sub-resources under parent: `/firs/{fir_id}/documents`
- Actions as verbs when required: `/firs/{fir_id}/extraction/approve`

### 1.5 Identifier Format

- Database integer PKs are exposed as-is in responses.
- FIR external identifier: `crime_no` (string, e.g., `BLR/ECD/2026/0051`) — used in API paths where human-readable reference is required.
- Internal IDs: integers (`fir_id`, `entity_id`, `candidate_id`, etc.).

### 1.6 Date and Time Format

All timestamps: ISO 8601 UTC — `2026-07-26T06:30:00Z`
Date-only fields: `2026-07-26`
All inputs and outputs in UTC. Display conversion is frontend responsibility.

### 1.7 Pagination

Standard query parameters for all list endpoints:

| Parameter | Type | Default | Max | Notes |
|-----------|------|---------|-----|-------|
| `page` | integer | 1 | — | 1-indexed |
| `per_page` | integer | 20 | 100 | — |

Standard paginated response envelope:

```json
{
  "items": [...],
  "total": 247,
  "page": 1,
  "per_page": 20,
  "total_pages": 13
}
```

### 1.8 Filtering, Sorting, Search

- Filter parameters: individual named query params, e.g., `?status=REGISTERED&district_id=5`
- Sort: `?sort_by=created_at&sort_order=desc` (default: `created_at` desc)
- Full-text search: `?q=Venkatesh Kumar` (applied to designated searchable fields)
- Date range: `?date_from=2026-07-01&date_to=2026-07-26` (ISO 8601 dates)

### 1.9 Standard Request Validation

All request bodies validated with Pydantic schemas. Validation errors return HTTP 422:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request body validation failed",
    "detail": {
      "field": "crime_registered_date",
      "issue": "Date cannot be in the future"
    }
  }
}
```

### 1.10 Error Envelope

All errors (4xx, 5xx) use:

```json
{
  "error": {
    "code": "STRING_CODE",
    "message": "Human-readable message",
    "detail": {}
  }
}
```

### 1.11 Correlation IDs

Every request carries `X-Correlation-ID` header (UUID4). If not provided by client, generated by `CorrelationIDMiddleware`. Included in every response header and every log entry.

### 1.12 Idempotency

- `POST /api/v1/firs` is NOT idempotent (generates new CrimeNo). Clients must not retry on timeout without checking for existing record.
- `POST /api/v1/firs/{fir_id}/extraction/approve` is idempotent (re-approving same queue_id has no additional effect).
- `POST /api/v1/entities/merge/{candidate_id}/approve` is idempotent (second call returns 200 with existing result).
- All `GET` endpoints are safe and idempotent.

### 1.13 Concurrency Control

FIR updates use optimistic concurrency via `updated_at` field:

- Client reads FIR → receives `updated_at` timestamp
- Client sends update with `If-Match: <updated_at ISO8601>` header
- Server returns 409 CONFLICT if `updated_at` has changed since client read

### 1.14 File Upload

Two-step for large files:

1. `POST /api/v1/firs/{fir_id}/documents` — upload multipart/form-data ≤ 10 MB
2. Server validates MIME from content, computes SHA-256, stores in Stratus, returns `{document_id, hash}`

No pre-signed URL pattern in MVP (Stratus access via server-side SDK only).

### 1.15 Rate Limiting

| Endpoint Group | Limit | Header |
|---------------|-------|--------|
| `POST /api/v1/rag/query` | 5 req/min per user | `X-RateLimit-Remaining` |
| `POST /api/v1/auth/login` | 10 req/min per IP | `Retry-After` |
| All other endpoints | No limit in MVP | — |

### 1.16 Audit Context

Every response for sensitive operations includes header:

```
X-Audit-Event-ID: <UUID of audit log entry>
```

### 1.17 Deprecation Policy

API v1 is the only version in MVP. Deprecation via `Deprecation: <date>` and `Sunset: <date>` headers in Phase 3+.

## 2. AI API Separation Principles

| Stage | Endpoint Pattern | Who Writes | What Changes |
|-------|-----------------|-----------|-------------|
| Request AI processing | `POST /firs/{id}/ai-analysis` | Officer | `int_FIRProcessingState.status` = NER_RUNNING |
| View AI suggestions | `GET /firs/{id}/extraction` | Officer (read) | None |
| Review (edit suggestion) | `POST /firs/{id}/extraction/review` | Officer | Queue item status = APPROVED_EDITED |
| Approve suggestion | `POST /firs/{id}/extraction/approve` | Officer | Target src_/int_ record created |
| Reject suggestion | `POST /firs/{id}/extraction/reject` | Officer | Queue item status = REJECTED |
| Save approved values | Implicit via approve | System (after officer approve) | `src_Accused` / `int_VehicleLink` / etc. |

**Rule:** `POST approve` is the only endpoint that writes to permanent `src_` or `int_` tables from AI data.

## 5. Integration Contracts

### 5.1 Frontend ↔ Backend API

| Field | Value |
|-------|-------|
| **Direction** | Frontend → Backend |
| **Protocol** | HTTPS REST JSON |
| **Auth** | Bearer JWT in Authorization header |
| **Retry** | 1 retry on network error (not on 4xx); exponential backoff |
| **Timeout** | 30 seconds per request |
| **Failure** | Show user-facing error toast; never crash page |
| **Sensitive data** | JWT in memory only; no sensitive fields stored in localStorage |
| **Correlation ID** | Client generates UUID4 per request; sent as `X-Correlation-ID` |

### 5.2 Backend ↔ Catalyst Data Store

| Field | Value |
|-------|-------|
| **Direction** | Backend → Data Store |
| **Protocol** | TCP; SQLAlchemy async ORM |
| **Auth** | DATABASE_URL in environment variable |
| **Retry** | 3 retries with 1s delay on connection failure |
| **Timeout** | 30s query timeout |
| **Failure** | Return 503 SERVICE_UNAVAILABLE; log error; alert via /health |
| **Sensitive data** | ORM parameters only; no raw SQL string construction |

### 5.3 Backend ↔ Catalyst Stratus

| Field | Value |
|-------|-------|
| **Direction** | Backend → Stratus (upload/download) |
| **Protocol** | HTTPS; Catalyst Stratus SDK |
| **Auth** | STRATUS_TOKEN environment variable |
| **Retry** | 2 retries on timeout |
| **Timeout** | 60s for upload; 30s for download |
| **Failure** | Return 503; EvidenceMaster INSERT rolled back |
| **Sensitive data** | File bytes streamed server-side; no client access to Stratus |

### 5.4 Backend ↔ AI Provider (OpenAI / Groq)

| Field | Value |
|-------|-------|
| **Direction** | Backend → External AI API |
| **Protocol** | HTTPS; httpx async |
| **Auth** | OPENAI_API_KEY / GROQ_API_KEY in environment |
| **Retry** | 1 retry on timeout; no retry on 4xx |
| **Timeout** | 30 seconds |
| **Failure** | Activate MockProvider; log WARN; return provider="mock" in response |
| **Sensitive data** | Only BriefFacts of approved FIRs sent; never real person names; MockProvider preferred |

### 5.5 Backend ↔ Background Task Engine

| Field | Value |
|-------|-------|
| **Direction** | Router → FastAPI BackgroundTasks |
| **Protocol** | In-process async call |
| **Auth** | None (same process) |
| **Failure** | Task failure logged; does not affect HTTP response |
| **Retry** | No automatic retry; manual re-trigger via API-FIR-008 |

### 5.6 Backend → Audit Log

| Field | Value |
|-------|-------|
| **Direction** | Service → audit_service → Data Store |
| **Protocol** | In-process; same async DB session |
| **Failure** | Log error; continue operation; no rollback |
| **Timing** | Written before response is returned |
