# Security Scanning

## Overview

Berunda uses multiple scanning tools at different stages of the development lifecycle to identify and remediate security issues.

## Tooling

| Scan Type | Tool | Stage | Trigger |
|-----------|------|-------|---------|
| **SAST** (Static Analysis) | CodeQL (Python, JS/TS) | CI | Every push to main |
| **DAST** (Dynamic Analysis) | OWASP ZAP | Pre-release | Before staging deploy |
| **Secret Detection** | TruffleHog | CI | Every push |
| **Dependency Scan** | pip-audit, npm audit | CI | Weekly + every push |
| **Container Scan** | Trivy | CI | Every push to main |
| **License Scan** | FOSSA / scancode | CI | Weekly |

## SAST — CodeQL

CodeQL runs on every push to `main` and on all pull requests. It analyzes:

- **JavaScript/TypeScript**: Injection, XSS, CSRF, auth bypass
- **Python**: SQL injection, command injection, path traversal, hardcoded secrets

## Secret Detection — TruffleHog

Scans the entire git history for:
- API keys and tokens
- Private keys (SSH, PGP)
- Database connection strings
- Cloud service credentials
- High-entropy strings matching secret patterns

**If a secret is detected:**
1. Immediately rotate the credential.
2. Remove the secret from git history (`git filter-repo`).
3. Update `.gitignore` and environment templates.

## Dependency Scanning

| Ecosystem | Tool | Action |
|-----------|------|--------|
| Python (pip) | pip-audit | Fail build on critical/high CVEs |
| Node (npm) | npm audit | Fail build on critical CVEs |

### Remediation SLA

| Severity | Remediation Time |
|----------|-----------------|
| Critical | 24 hours |
| High | 72 hours |
| Medium | 7 days |
| Low | 30 days |

## Container Scanning — Trivy

Scans all Docker images for:
- OS package CVEs (Alpine, Debian)
- Language-specific vulnerabilities
- Misconfigurations
- Embedded secrets

## Reporting

Scan results are uploaded as SARIF artifacts and visible in:
- GitHub Security tab
- GitHub Actions run logs
- Weekly security report (generated by workflow)
